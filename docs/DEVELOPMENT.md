# WriteUP — Development Log

> Living document. Updated as the project develops. Tracks decisions, data collected, and progress.

## Vision

**WriteUP** converts pasted text into perfectly realistic handwritten page(s):

- Paste text in → pick paper image(s) → pick/learn a handwriting style → render → perfectly blended handwriting on the photographed page.
- Computer vision finds the page inside a photo (paper may fill the frame or sit on a background), rectifies it, respects padding settings, renders handwriting, and warps it back so it blends with the original photo's perspective, lighting and texture.
- Handwriting styles are **learned from real handwriting samples** (slant, glyph size, line spacing, baseline wander, ink colour) and applied to handwriting fonts with per-glyph perturbation.
- Everything is adjustable: padding, font scale, line spacing, ink colour, slant, jitter, rotation, opacity, blur.
- Text scales with the page: sizes are stored relative to page height, so the same settings work across pages of any resolution.
- Pages can be defined per-insert via images: one paper image per page, or reuse.
- The page image does **not** need to be empty — handwriting blends over existing print/texture.

### Rendering pipeline (the core idea)

1. **Page detection (CV)** — find the paper quadrilateral in the photo
   (threshold → contours → 4-point approximation → ordered quad).
2. **Rectify** — perspective-warp the page to a canonical rectangle.
3. **Layout** — word-wrap text in canonical page space using padding settings;
   font size is a fraction of page height → text scales with the page.
4. **Handwriting render** — draw each glyph with per-character rotation, scale,
   baseline offset and spacing jitter sampled from the learned style; apply
   slant shear; ink colour with subtle variation.
5. **Blend** — warp the ink layer back into the photo with the inverse
   perspective matrix; alpha/multiply composite + micro-blur + ink-bleed noise
   so it sits *in* the paper, not *on* it.

### Style learning (CV, no heavy ML)

From a handwriting sample image we measure:

| Parameter | Method |
|---|---|
| Ink colour | Median colour of dark (ink) pixels |
| Slant angle | Shear-scan maximizing vertical-projection variance |
| Glyph height | Connected-component height distribution (robust median) |
| Line spacing | Horizontal projection profile peak distance |
| Baseline wander | Std-dev of component centres around fitted baselines |
| Size variance | Spread of component heights → per-glyph scale jitter |
| Space width | Gap distribution between components on a line |

Values are normalised relative to the sample image height so a learned style
transfers to pages of any size.

## Data collected

- `data/fonts/` — OFL handwriting fonts (Google Fonts): base glyph shapes.
- `data/papers/` — paper photos (synthetic generator: plain/ruled/graph, with
  and without desk backgrounds, perspective + lighting + noise).
- `data/samples/` — handwriting sample images used for style learning
  (generated by rendering known text with varied fonts/slants, then measured
  back — closed-loop validation of the learner).
- `data/writeup.db` — SQLite: papers, styles, renders, settings.

## Known limitations / future ideas

- Text is not auto-aligned to existing ruled lines on the paper (pitch is
  learned from the *style*, not the page). A "snap to rules" mode could
  measure line pitch from the page photo itself.
- Glyph shapes come from fonts; a future sampler could cut real glyphs from
  the sample image and reassemble them (true handwriting forgery mode).
- Detection assumes a roughly rectangular, mostly-visible page.
